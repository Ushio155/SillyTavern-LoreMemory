## 两个版本：开发者版 / 面向用户版

源码只有一份，`node build.mjs` 会产出两份可直接安装的包（在 `release/` 下）：

| 包 | 版本 | 界面差别 | 给谁 |
|---|---|---|---|
| `release/SillyTavern-LoreMemory-dev/` | `0.2.0-dev` | 多一个**整行**的「灌入演示节点」+ `/lm-seed` 命令 + 标题上的「开发版」徽标 | 开发/调试：不用真的聊满 N 楼就能看到效果（内置剧本） |
| `release/SillyTavern-LoreMemory/` | `0.2.0` | **没有**演示入口，它原来那一格直接换成「管理聊天书」 | 真实用户 |

两个版本的按钮区（**在「刷新 / 清空记忆」下面**；用户版是把演示键那一格换成「管理聊天书」，
不是再加一行 —— 演示入口在用户包里根本不存在，空着那一格会留个洞）：

```
开发者版：[立刻总结未总结的消息] [刷新] [清空记忆]   ← 同一行里三个键等宽，一起铺满整行
          [        灌入演示节点        ]   ← 整行，仅开发者版
          [        管理聊天书          ]   ← 整行
用户版  ：[    立刻总结未总结的消息    ] [ 管理聊天书 ]   ← 2×2 四格铺满（手机端就是这个形状）
          [          刷新            ] [  清空记忆  ]
```

状态行（四格）在两个版本、宽窄屏下都是 **2×2 两行铺满**，宽度固定两列 —— 不随面板宽度变列数：
`repeat(auto-fit, minmax(110px, 1fr))` 那种写法在宽面板上会排成 3+1，第四个格子单独占一行、
右边空一大片（桌面端踩过）。窄屏漏单的按钮（开发者版那行三个键落到第二行只剩「清空记忆」）
用 `:last-child:nth-child(odd)` 铺满整行，不留空洞。

**「灌入演示节点」在用户版里不是"藏起来"，而是不存在**：按钮不渲染、斜杠命令不注册、
`window.LoreMemory.seedDemo` 也不挂 —— 演示节点是内置剧本，用户点了会往自己的书里灌一段
不属于他的故事。构建开关只有一处：`src/build.js` 的 `DEVELOPER_BUILD`。

> ⚠️ 两个包**不要同时安装**：它们用的是同一个 `extension_settings.LoreMemory` 与同一份
> `chat_metadata` 状态，同时加载会出现两个面板抢同一份数据。
> 校验产物与源码是否一致：`node build.mjs --check`（测试套件里的 `check-build.mjs` 就是跑这个）。

## 安装（含手机）

**方式一：面板安装**

`扩展程序`（魔法棒 🪄）→ `Install extension` → 填仓库地址，分支填 `dev`：

```
https://github.com/Ushio155/SillyTavern-LoreMemory
```

**方式二：手动放目录**

把仓库内容整个放进：

```
<SillyTavern数据目录>/data/<用户名>/extensions/SillyTavern-LoreMemory/
```

（要求 `manifest.json` 就在该目录下——仓库根目录的结构就是按这个来的。）

> 想装**面向用户版**：用 `release/SillyTavern-LoreMemory/` 那个文件夹（先 `node build.mjs` 生成）。
> 仓库根目录这份源码是**开发者版**（含演示入口）。两者差别见上面「两个版本」一节。

装好后**刷新浏览器页面**。手机上 ST 的扩展同样适用；面板已做 ≤640px 的移动端适配
（按钮两行等宽、设置行改为上下堆叠、输入框 16px 防 iOS 聚焦缩放）。

> ⚠️ **只保留一份副本，而且要知道是哪一份在生效**。同名扩展同时存在于「用户目录」和
> `public/scripts/extensions/third-party/` 时：
>
> - `/api/extensions/discover` 只报**一条**，类型是 `local` —— 全局的同名条目在列表阶段就被剔除了
>   （`src/endpoints/extensions.js`，`In case of a conflict, the extension will be loaded from the user folder`）；
> - 但浏览器**真正收到的字节来自 `public`**：`app.use(express.static(public))`（`src/server-main.js:242`）
>   挂在用户扩展路由（`src/users.js:1219`：先查用户目录、找不到才回落 `public`）**之前**，
>   只要 `public` 里有同名文件，静态中间件就先把它发出去了。
> - **实测**（`driver.mjs` 的 `[I]` 段把这条钉成了断言）：用户目录放 `0.2.0`、`public` 放 `0.2.0-dev` 时，
>   `discover` 报 `local`，而页面里跑的仍是 **`0.2.0-dev`**，面板上照旧有演示按钮。
>
> 结论：**换版本必须换掉 `public` 里那份**。只往用户目录丢一份新的是没用的 ——
> 这正是"两份副本、界面里生效的说不清"这个坑的另一半。
> `install.ps1` 会**先清掉旧副本再装**，`-Release user|dev` 用来选装哪个包。

## 30 秒看懂它是什么

边聊边把历史切成一条条"记忆节点"写进**当前聊天的世界书**；
平时这些节点安静躺着**不花一个 token**，只有被聊到时才按优先级挤进上下文。

它**不自己实现检索**——扫描、关键词匹配、粘滞/冷却、预算裁剪全部是 SillyTavern 原生世界书在干活。
插件只做两件事：**内容生产线**（切段 → 摘要 → 写成条目）和**仪表盘**（读 ST 的扫描结果做账本）。

## 生成设置（面板里可改，全局生效）

打开「生成设置」折叠区即可调，全部持久化在 `extension_settings.LoreMemory`，对所有聊天生效：

| 设置 | 说明 |
|---|---|
| **自动记忆** | 打开后进入聊天**自动建书并绑定**（只认真正的聊天：停在欢迎屏/没选角色卡时不会建，见文末「维护：清理空书」）；之后每满 N 条消息**自动总结**成节点。默认**关**——它会真的调用你配置的 API |
| **每多少条消息总结一次** | 对应 memory 扩展的 "Update every N messages"。面板会显示「还差几条触发」 |
| **总结时扫描哪些消息** | `角色 + 用户` / **`仅角色对话`** / `仅用户输入`。选"仅角色"时，用户发言不会进入摘要 |
| **转录里带发言人名** | 关掉更省 token，但摘要更难分辨谁在说话 |
| **摘要目标长度（字）** | 替换提示词里的 `{{words}}`，同时用于长度告警 |
| **骨架目标长度（字）** | 替换骨架提示词里的 `{{skeletonWords}}`。**与节点长度解耦**：骨架每回合都注入，默认 120 字，明显小于节点的 200 |
| **单次生成读入的记录上限（token）** | 拼进提示词的聊天记录上限，默认 **2000**。**这是最容易被忽略、也最容易炸的一项**：记录是塞进提示词正文的，而 ST 把这条当**"必需"消息**——超预算不会被优雅丢弃，而是直接报「必要的提示词超过了上下文大小」。骨架取**最新**的若干楼；节点摘要从**最旧**那头装满一块、剩下的下次继续（会提示「本次只总结了第 X-Y 楼」）|
| **摘要时不带世界书与作者注** | 省 token，也避免记忆条目自己触发自己 |
| **每多少条消息刷新骨架** | 骨架是那条常驻的「现状卡」，0 = 不自动刷新。刷新的输出会先过**硬闸门**：只保留状态字段行（丢弃场景/对白/心理描写），并裁到「骨架条目上限」以内 |
| **摘要提示词** | 完全可编辑，带「恢复默认」按钮。占位符：`{{messages}}` `{{words}}` `{{count}}` `{{from}}` `{{to}}` `{{char}}` `{{user}}`；未知占位符会原样保留并在面板告警 |
| **骨架「现状卡」提示词** | 单独一条提示词，额外支持 `{{previous}}`（上一版现状卡）与 `{{skeletonWords}}`（骨架目标长度） |
| **骨架条目上限（token）** | **真的会生效**：超出就按 `状态变化 → 未结钩子 → 在场` 的顺序整段丢弃，丢不动了就截断最长的字段正文。「当前阶段」只允许被截断，不允许被整段丢掉 |
| sticky / cooldown / 节点上限 / 热点扫描深度 / 告警线 | 条目字段与面板行为 |

**优先级阶梯（`order`）真的在用了**：每个节点有一个「主线 / 支线 / 细节」下拉，
对应条目 `order` 的 **500 / 300 / 100**；骨架固定 900。ST 按 `order` **降序**吃预算，
所以预算紧张时先被挤掉的是细节、最后才是主线 —— 这就是"分层召回"。
模型可以在摘要时给出 `tier` 建议（默认提示词已要求），你也可以随时在下拉里改。

**自定义提示词改坏了会怎样**：不会崩。若模型输出里没有 JSON，插件会退化成
「整段当正文 + 兜底抽词」，并把节点标为**待确认并暂时禁用**，等你点节点行的
**「改关键词」**修好后手动启用——保底不会污染上下文。想恢复就点「恢复默认」。

**关键词会自动过滤两遍**（这是提示词做不到的那一层）：

1. **结构自检**：1 个字的关键词、超高频黑名单（剑 / 人 / 这里 …）→ 标待确认。
2. **判别力自检**：拿**你这本聊天的真实消息**算每个词的出现率——
   在**本节点楼层之外**出现率 ≥25%，或全局出现率 ≥50% 的词会被**自动剔除**
   （它们会在别的剧情里也命中，是误触发的主要来源），并在节点行下注明剔了哪些。
   留下来的词一个不动：只要一个词只在你这段剧情里出现，它就是好关键词。

> 为什么需要第 2 条：真实案例里 14 个关键词只有 2 个是元凶（出现率 54% 和 49%），
> 被三个节点共用 → 任一出现就同时点亮三个节点、白烧 367 token/回合，与当前剧情无关。
> 剔除后节点仍会被召回，只是不再到处乱触发；**若某个节点的词被剔光**，
> 它会标成「待确认」并禁用，等你用「改关键词」补回来。

## 3 分钟看到效果

1. 打开任意一个**有角色、有消息**的聊天。
2. 点顶部魔法棒 🪄 → **记忆节点 · LoreMemory**，滚到面板。
3. 让插件写点东西进去，两种方式：
   - **开发者版**：点 **「灌入演示节点」** —— 不用真的聊 60 楼，立刻得到 5 个节点 + 1 条骨架。
   - **用户版 / 任何人**：点 **「立刻总结未总结的消息」**（或打开「自动记忆」让它自己总结）。
   同时打开 ST 自带的世界书面板，你会看到这本书里的条目**就是插件刚写进去的**；
   在面板点「管理聊天书」也能在插件里直接看这些条目。
4. 在聊天框发一句含 **`魔界`** 或 **`缇娜`** 的话 → 面板「本回合注入了什么」立刻列出被注入的节点、
   **命中原因**和估算 token。
5. 换成一句完全不含关键词的（比如「今天天气不错」）→ 注入量只剩骨架那一条。
   **这就是"平时不花钱"。**
6. 连发几句都提到 `魔界` → 节点先 **粘滞 4 楼**、再 **冷却 16 楼**，不会每回合重复注入。
7. 点某条节点的 **「钉选」** → 本回合必定注入（下一回合自动失效）。

> 想验证**自动总结**：打开「自动记忆」，把「每多少条消息总结一次」调到 3，
> 然后正常聊几句 —— 面板的「未总结」会先倒计数，到点后后台静默总结出一个新节点。
> 也可以随时点「立刻总结未总结的消息」不等阈值。

> 面板底部的「怎么验证这个插件真的在工作」把上面这几步也写在界面里了。

## 面板上能看到的

整个面板就是**一个可折叠块**（和「向量存储 / 摘要」这些内置扩展同款，用的是 ST 自己的
`inline-drawer`，外观与动画跟随主题）。**收起时标题行仍带摘要**
（书名 · 节点数 · 未总结条数 · 待确认/超预算告警），所以不用展开也知道现在什么状况。

展开后里面是 5 个子折叠区，各自独立开合，**展开状态会被记住**（不会被下一次扫描结果关上）：

| 区域 | 内容 |
|---|---|
| 状态行 | 当前书 / 节点数 / **本回合注入 token + 占上下文比例** / 近 20 回合均值 |
| 本回合注入了什么 | 条目名 + **命中原因**（常驻 / 关键词命中 / 粘滞延续 / 钉选）+ token，含合计 |
| 记忆节点 | 标题、楼层区间、关键词 chip、token（超上限标红）、命中次数、**优先级下拉**、状态徽标、行内操作（钉选 / 禁用 / 看正文 / **改关键词** / **回滚正文** / 重摘要 / 删除） |
| 最常被召回的节点 | 命中次数 Top 5 |
| 建议的世界书设置 | 当前值 vs 建议值对照（**只展示，不偷偷改你的全局设置**） |

> 从魔法棒菜单点进来时，如果面板本来是收起的，插件会**自动把它展开**再滚动定位 ——
> 不会出现"点了没反应"。

## 斜杠命令

| 命令 | 作用 |
|---|---|
| `/lm-list` | 列出所有节点（id / uid / 区间 / token / 状态 / 命中次数 / 关键词） |
| `/lm-books` | 列出插件建过的聊天书并打开「管理聊天书」弹窗（两个版本都有） |
| `/lm-seed` | 灌入演示节点（**仅开发者版**：用户版不注册这条命令） |
| `/lm-now` | 立刻把「未总结的消息」总结成一个节点（不等阈值） |
| `/lm-skeleton` | 立刻用当前骨架提示词重写「现状卡」 |
| `/lm-auto on\|off` | 开关自动记忆 |
| `/lm-interval 12` | 设置每多少条消息总结一次 |
| `/lm-scope all\|char\|user` | 设置总结时扫描哪些消息（all=角色+用户，char=仅角色，user=仅用户） |
| `/lm-pin N003` | 强制某节点本回合注入一次 |
| `/lm-recall 魔界` | 即使最近没提到"魔界"，也让相关节点被召回 |
| `/lm-status` | 一行状态摘要（含未总结条数与阈值） |
| `/lm-clear` | 删掉本书里的全部记忆条目（书本身保留） |

## 这个 demo 做了什么 / 没做什么

**真实的部分（不是前端假动画）**

- ✅ 真的创建并绑定**聊天世界书**（`chat_metadata['world_info']`），换聊天自动隔离
- ✅ 真的用 ST 的 `createWorldInfoEntry` / `saveWorldInfo` 写条目落盘，字段取值对齐 1.18.0
- ✅ 真的走 ST 原生扫描：关键词命中、`sticky`/`cooldown`、`order` 优先级、`atDepth` 注入、预算裁剪
- ✅ 真账本：读 `WORLDINFO_SCAN_DONE` 事件里 ST 自己报的激活条目，不是插件自己模拟的
- ✅ `/lm-pin`、`/lm-recall`、禁用/删除/清空都是真的在改世界书
- ✅ 「管理聊天书」的**查看内容 / 新增 / 绑定 / 删除**都是真的在读、写、删世界书**文件**
  （删除走 ST 的 `deleteWorldInfo`，会一起清掉全局选择与缓存，不是只删了界面上的那一行）
- ✅ `/lm-now` 用 `generateQuietPrompt` 走真实 LLM 摘要（需自备 API）

**为了"立刻看到效果"而简化的部分**

- ⚠️ **演示节点是内置剧本**（一段"魔界狩猎场"的故事），不是从你的聊天里总结的。
  真实的自动/手动摘要功能是完整实现的（见上面「生成设置」）。
- ⚠️ 骨架条目在你灌演示节点时写一次；自动刷新由「每多少条消息刷新骨架」控制（默认 24）。
  模型输出会先过**硬闸门**（见上面「生成设置」）：只留状态字段、裁到条目的 token 上限；
  **一个状态字段都没有就整次拒收、保留原卡** —— 不会把一篇小说写进世界书。
  手动把骨架**禁用**之后，自动刷新会绕开它（不会静默复活）；想恢复就点一次「立刻刷新骨架现状卡」。
- ⚠️ 自动总结是**串行单飞**的（同时只跑一次），并且会等 1.5 秒才开始，避免和你的输入抢 API。
  ST 真正的"非阻塞摘要"模式（memory 扩展的 prompt_builder 选项）没有实现。
- ⚠️ token 数是**估算**（中文按约 1.2 字/token 取保守偏高的系数），用于量级判断与预算告警，不是精确计数。
- ⚠️ 没有做：向量召回、跨聊天记忆、多 API 支持、节点自动归档、导出/导入。

**关于自动总结的成本**：打开「自动记忆」后，每满 N 条消息会真实调用一次你配置的 API。
默认**关闭**就是为了避免你没注意时静默花钱。省的是**输入** token，花的是**摘要生成** token——
净收益通常为正，但这不是零成本。

## 管理聊天书

面板上的 **「管理聊天书」** 按钮（两个版本都有：开发者版里它占一整行，用户版里它顶在
「灌入演示节点」原来那一格）会弹出一个窗口，把**插件建过的聊天书**
全部列出来 —— 这是用户版的"记忆管理入口"：不用去 ST 的世界书面板里翻，也不会误删别人的书。

| 列表里看到的 | 说明 |
|---|---|
| 书名 | `LM-<角色名>-<聊天id前8位>`，比如 `LM-林晚-1a2b3c4d`；重名会自动加 `(1)` |
| 「当前聊天」徽标 | 这个聊天正在用的那本（只可能有一本） |
| 「不是插件建的」徽标 | 当前聊天**手动**绑了别的书时也会列出来，但只读、**不给删除按钮** |
| 「磁盘上没有」徽标 | 绑定还指着它、文件却已经不在（外部删过） |
| `N 条目 · M token` | 这本书里现在有多少条目、大约多少 token |
| 「清理空书」| 收拾历史遗留的垃圾空书，见下一节 |

每本书一行操作：

| 操作 | 行为 |
|---|---|
| **查看内容** | 就地展开这本书的全部条目：uid、标题、关键词 chip、`常驻` / `已禁用` 徽标、order、**正文全文** |
| **绑定到当前聊天** | 把这本书改绑给当前聊天（会先弹确认）。换绑**不会删**原书，但面板上的节点列表与游标会清零 —— 那些记的是原来那本书的内容 |
| **在 ST 面板打开** | 关掉弹窗，直接跳到 ST 自带的世界书编辑器，并选中这本书 |
| **删除** | 永久删除世界书文件（不可撤销）。删的若是**当前聊天绑定的那本**，会连带解除绑定并把面板状态清零 —— 确认框里会写明这三件事 |
| **新增聊天书** | 给当前聊天**再建一本** `LM-` 书并绑定过去（旧书保留在磁盘上，随时能绑回来） |

列表**按角色卡分组**：书名是 `LM-<角色卡名>-<聊天片段>`，所以同一张卡下聊过好几次攒出来的书会收在
同一个**可折叠的组**里（组头写角色卡名 + `N 本 · M 条目 · T token`；当前聊天那本所在的组会打标，
整组都是空书的也会标出来 —— 收拾垃圾书时好找）。默认全展开、不藏东西；收起只是隐藏 ——
书行、按钮、已展开的条目都还在 DOM 里，折叠状态记在弹窗状态上，重绘不丢。

> 为什么"换书 = 状态清零"：面板上的节点列表、游标、骨架 uid 记的都是**当前那本书**的内容。
> 换书却留着它们，面板就会显示一堆指向不存在条目的节点，下一次写入还会去建一本新书 —— 用户完全看不懂。

> 弹窗是挂在 `body` 上的浮层（不是面板里的又一个折叠区）：长列表 + 条目正文需要能自己滚动，
> 而面板本身在 ST 的「扩展程序」CSS 抽屉里，塞长内容会被裁掉。按 `Esc`、点遮罩、点「关闭」都能收起。

**手机（≤768px）上它不是弹窗，而是整整一页**（仿 CardLore 的「一键生成」页）：卡片铺满屏幕、
没有圆角边框；标题栏是**实心主题色**并**吸顶**（滚多远都能按到 ✕），标题栏里只留「这是什么 + 怎么关」——
「几本 · 当前绑定哪本」挪到它下面单独一行；整页就一个滚动容器、正文不再自己滚；
滚动条收细到 6px（手机上只用滑动，宽槽既挤内容又会露出后面那层界面）。
整页的**遮罩是半透明的**（`rgba(0, 0, 0, 0.55)`，与桌面端同值），并且写在**滚动容器自己**身上
（不是那个 `position: absolute` 的 backdrop 子元素 —— 它只盖得住第一屏，往下滚就露出后面那层）。

> 手机整页模式为什么不能把遮罩做成实心色：卡片铺满整屏，眼睛看到的透明度 = **遮罩 × 面板**，
> 遮罩一旦是 `#1c1c22` 这种实心色（alpha = 1），透过去就是一块死色 ——
> 用户原话「整页都看不到下方页面」。上一版正是「纯色兜底 + 主题色渐变层」的写法，已经实测回退；
> 现在卡片自己**不再覆盖底色**，回落到 `--SmartThemeBlurTintColor`，跟着你主题的透明度走。
> 一句话：**面板越"铺满"，遮罩层越不能实心。**
> （同一条结论在 CardLore 的 `cardlore.css` 手机段里也留了注释，两边是同一套结构。）

> 标题栏为什么必须是实心的：它吸顶之后，下滚的正文会**从它底下经过**。只要有一点点透明，
> 两层文字就叠在一起（用户实测截图里「管理聊天书」和「清理空书」糊成一团）。
> 实心色用的是 `--SmartThemeQuoteColor` —— 就是你在 ST 主题设置里选的强调色，颜色跟着你的主题走。
> 注意这跟卡片底色是**两件事**：卡片可以（也应该）跟主题一样半透明，吸顶标题栏必须自己实心，
> 不靠卡片兜底。

> 为什么手机上必须换形态：`position: fixed` 的浮层在 ST 里会**塌成 0 高** ——
> ST 给 `<html>` 加了 `-webkit-transform: translateZ(0)`，`<html>` 就成了 fixed 后代的包含块，
> `inset: 0` 不再等于视口（实测 390×0，卡片跟着 0×0，DOM 里明明有书有条目但屏幕上什么都没有）。
> 现在容器用显式 `100vw / 100dvh`；而"卡片内部再滚一层"在真机上还容易失效、底部按钮够不着，
> 所以窄屏直接给一整页。（这条是照 CardLore 踩过的同一个坑做的，它们的 CSS 注释里记着结论。）

## 维护：清理空书

**入口在「管理聊天书」弹窗里**（以前在「生成设置」最底下，现在归到书的管理里）。

*为什么会有垃圾书*：早期版本会把 ST 的**欢迎屏**（选角色卡那一屏）误当成一个聊天 ——
那一屏会往聊天区塞一条助手问候语（「如果您已连接到一个 API，试着问我点什么吧！」），
看起来"有内容"，但它其实没有聊天文件、也没有选中的角色。插件给它建的书**永远绑不上任何聊天**，
于是每次刷新都新建一本：`LM-xxx-nocid`、`LM-xxx-nocid (2)`……

现在建书前会先确认"真的在一个聊天里"（`src/context.js`），这条路已经堵死了。
但已经生成的空书还在你的世界里，所以提供了这个按钮。

**它只删同时满足这三条的书**，一条不满足就不动：

1. 名字以 `LM-` 开头（本插件建的）
2. 里面**一条条目都没有**（空书不含任何信息，删掉不会丢数据）
3. 不是当前聊天绑定的那一本

删之前会弹确认框，把要删的书名列给你看。有内容的书**一律不动**。

```
SillyTavern-LoreMemory/
├─ manifest.json        ST 扩展清单（开发者版：0.2.0-dev）
├─ index.js             唯一 import ST 内部模块的地方（相对路径的目录深度只写一次）
├─ lorememory.css       面板样式 + 「管理聊天书」弹窗（含 ≤640px 移动端适配）
├─ build.mjs            打包：同一份源码 → release/ 下的开发者版与面向用户版
├─ release/             打包产物（生成物，不要手改）
│  ├─ SillyTavern-LoreMemory/      面向用户版：无演示入口，有「管理聊天书」
│  └─ SillyTavern-LoreMemory-dev/  开发者版：多一个整行的「灌入演示节点」
├─ README.md
└─ src/                 全部是零依赖纯函数，可在 Node 里直接跑回归
   ├─ build.js          唯一的构建开关 DEVELOPER_BUILD（两个版本只有这里不同）
   ├─ store.js          chat_metadata 状态形状、归一化、账本、统计
   ├─ entry.js          节点 → 世界书条目字段补丁（对齐 1.18.0 字段表）
   ├─ guard.js          骨架硬闸门（字段白名单 / 裁剪 / 拒收）
   ├─ context.js        「是不是真聊天」判定（欢迎屏空书的守卫）
   ├─ seed.js           演示剧本数据 + 关键词质量自检（仅开发者版使用）
   ├─ tokens.js         token 估算
   └─ ui.js             面板与弹窗渲染 + HTML 转义
```

**为什么要这样分层**：ST 第三方扩展的 `import` 走相对路径，路径层级取决于文件在目录树里的深度，
是最容易写错的地方（CardLore 的技术总结专门记过这个坑）。把所有 ST import 集中到 `index.js`，
`src/` 下就只剩纯函数——既不会踩层级坑，也能在 Node 里做离线回归。

## 已知限制

1. **召回率本质上受限于世界书机制**：关键词**只扫最近 N 条消息**（全局默认仅 2 条）。
   本插件保证的是"**被再次提及过的**旧细节能被召回"，不保证"任何旧细节都能召回"。
   想拉高召回：调全局扫描深度、设 `min_activations` 扩窗、用 `/lm-recall`、或点钉选——**都是拿 token 换的**。
2. **不要把主角名当关键词**。ST 默认 `world_info_include_names = true`，扫描缓冲里每条消息都带
   「角色名: 正文」前缀，所以「林晚」这类关键词等于**每回合必中**，节点永远常驻，直接毁掉"平时不花钱"。
   人物名应该出现在摘要正文里（那是内容），不该出现在 `key` 里（那是触发器）。
3. **摘要本身要花 token**。省的是**输入** token，花的是**摘要生成**的 token——净收益通常为正但必须量化，
   不能宣称"零成本"。
4. **`/lm-recall` 会多花一点点**：它靠 `setExtensionPrompt(..., scan=true)` 把关键词并进扫描缓冲，
   那几个词本身也会进 prompt。
5. 记忆是**每聊天**的，不随角色卡走；跨设备迁移目前只能手动导出世界书 JSON。
